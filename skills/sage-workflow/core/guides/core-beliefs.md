# 核心信念 — 智能体优先操作原则

> 本文件定义了 SAGE 项目的核心工程信念。
> 所有智能体的行为和仓库的演进都必须与这些原则保持一致。
> 最后更新: 2026-05-28

## 1. 闭环驱动 (Closed-Loop First)

智能体内部自动重试（测试失败→修复→重测，最多 3 次），超限才上报人类。
纠错成本低，等待成本高。在智能体吞吐量远超人类注意力的系统中，让智能体自主解决问题是默认行为。

## 2. 约束代码化 (Constraints as Code)

通过强制执行不变量，而非对实施过程进行微观管理。
用验证脚本替代文字禁令。用 linter 替代"请注意..."。
能进入 linter 的约束，不停留在提示词里；能转成验收 oracle 的意图，不停留在愿望描述里。
一旦编码为规则，它们就能立即、一致地应用于所有地方。

## 2.1 可证伪契约 (Falsifiable Contract)

TASK 是意图契约，不是 PRD，也不是实现蓝图。
它锁定可接受实现空间：接口契约、行为约束、边界条件、验收标准和证据链。
不可验证的描述会腐烂；过度详细的蓝图会漂移。每条关键断言都应能被测试、脚本、日志、截图或明确人工步骤证伪。

## 3. 渐进式披露 (Progressive Disclosure)

给智能体地图，不给百科全书。
智能体按需加载项目上下文，不全量灌入。
AGENTS.md 是入口目录，目标 ≤80 行，超过 100 行拆到 T2；入口规则必须可执行，不能为了压缩行数删除关键行为规则。

## 4. 品味可执行 (Executable Taste)

人类的品味一旦被捕捉，就持续应用于每一行代码。
审查评论、重构的 PR 和面向用户的 Bug 被记录为文档更新，或直接编码到验证工具中。
当文档不够完善时，把规则转化为代码。

## 5. 仓库即大脑 (Repo as Brain)

智能体看不到的就不存在。
存储在 Google Docs、聊天记录或人们头脑中的知识都无法被系统访问。
代码仓库本地的、已版本化的工件是智能体能看到的全部。

## 6. 最小情境原则 (Minimal Context)

情境是一种稀缺资源。一个巨大的指令文件会挤掉任务、代码和相关文档。
过多的指导反而变得无效。当一切都"重要"时，一切都不重要了。

## 7. 熵必须清理 (Entropy Garbage Collection)

技术债就像高息贷款：不断以小额方式偿还，总比让债务累积再痛苦一次解决好得多。
定期运行后台文档治理和质量扫描任务，持续发现和修复不良模式。
